What changed and why
---------------------
After renaming files or saving tags, music players and Gallery kept showing the old names / old tags, because
Android's media library (MediaStore) had not rescanned the files.

1. Native (FoldersPlugin.java): new method scanMedia({ paths } or { uri, ids }). It calls
   MediaScannerConnection.scanFile for the given files. Paths that exist are (re)indexed with their new tags;
   paths that no longer exist (old names) are dropped from the library. For a picked folder, document ids of
   the phone's own storage and SD cards ("primary:Music/a.mp3") are converted to file paths. Before Android 10
   the files inside renamed folders are listed explicitly, since the old scanner does not walk folders.
2. sources.js: SafRoot (Open folder) and NativeRoot (in-app file browser) record every file they rename,
   write, patch in place or delete - old and new paths, and the files inside a renamed folder.
3. jobs.js + media-index.js: when any job ends (rename, extension rename, tag save, restore, batch), the
   changed files are sent to scanMedia. This is the default; it also runs after Stop or an error, never fails
   a job, and does nothing in the browser, for ZIPs/imports, or on an older APK without scanMedia.
   (Hidden opt-out for troubleshooting: localStorage 'nametag.mediaIndex' = 'off'.)
4. tests/media-index.test.mjs (in npm test): renames incl. folder renames, tag saves, SAF ids, Stop/error,
   opt-out and old builds.
