How NameTag works

Everything runs inside your browser. Files never leave your device, and the app works offline once installed. Online lookups (MusicBrainz, Cover Art Archive, LRCLIB) only run when you ask for them.

Renaming safely

  1. Open a folder, a ZIP, or import files. Nothing changes yet.
  2. Build a list of rules. They run top to bottom, and the preview updates as you type: removed characters are struck through, added ones are highlighted.
  3. The pattern analyser reads the current names, shows the pattern it found (for example [##]_[text]) and proposes a cleaner one with ready-made rules.
  4. Press Rename. NameTag first writes an undo file named nametag-rename-DATE.json into the top of the folder or ZIP, then renames. Clashes get “ (2)”, invalid names are skipped, swaps and case-only changes go through temporary names.
  5. Renames and tag saves run in the background. A progress card appears at the top: you can open other screens, edit other files or switch to another app and it keeps going. Files are processed in parallel, but each file keeps its own number and tags. With several folders open, tick a whole folder (or single files) to choose what is renamed or saved; Save in the Tag editor writes the ticked files that have changes. Stop finishes the items already started and leaves the rest untouched. If the app is closed mid-way, Undo puts back what was done, and Resume (in History) finishes the rest.
  6. To go back, choose Restore, open the same folder, and pick the undo file. It also works from the History tab, or on another computer.

Changing extensions

Choose Extensions at the top of the Renamer. It works on a folder, a ZIP or imported files, subfolders included. Every extension found is listed with its count: type a new one next to any group (- removes it), or use the quick options: letter case, unify spellings (jpeg to jpg, htm to html), fix extensions that do not match the file contents, and add missing ones. It writes the same undo file as any rename, so Restore puts the old extensions back.

Restoring on another computer

Undo and backup files store paths relative to the folder or ZIP that was changed, never the full path on your disk, so they travel with the files. On the other computer:

  1. Open the folder, ZIP or imported copy that holds the files. It can be the same folder, its parent, or wherever the ZIP was extracted. Undo files are found in subfolders too.
  2. Only have the JSON file? In Restore, choose Open an undo file first (or Open a backup file first in the Tag editor), then pick the folder.
  3. NameTag lines the saved paths up automatically and shows how many items it found. If the files sit elsewhere, use Choose the folder on this computer, or adjust the two boxes: skip leading folders of the saved paths, and the subfolder the files are in here. Subfolders that were renamed or moved are found by unique file names.
  4. Check the preview, then restore.

Template variables

Use these in the Build from template rule, in Add text, and in the Replace with box of Find and replace. Add a fallback with |, for example {artist|Unknown}.

VariableGives
{name} {original} {ext}Current name (after earlier rules), the original name, the extension
{n} {n:3} {dn:2} {total}Counter across all items, padded to 3 digits, counter within the folder, number of items
{parent} {parent:2} {root} {path:-}Folder name, grandparent folder, the opened folder, the relative folder path joined with “-”
{mdate:YYYY-MM-DD} {now:HH.mm}Date modified or today, with tokens YYYY YY MMMM MMM MM M DD D dddd ddd HH hh mm ss A
{w:1} {w:-1} {c:1-4}First word, last word, characters 1 to 4
{size} {bytes} {rand:6} {uuid}File size, bytes, random letters, a random ID
{artist} {title} {album} {albumartist} {track:2} {disc} {year} {genre}Audio tags, read automatically when you use them
{bitrate} {duration} {samplerate} {codec}Audio properties

Tag editor

Select one file or many. With several selected, fields that differ show ‹keep›; leave them and every file keeps its own value. Saving writes nametag-tags-DATE.json with the previous values (and previous covers when they changed) before touching any file. Restore writes those values back and makes a new backup, so a restore can also be undone.

Tools include Filename to tags (%artist% - %title%, folders with /), auto-numbering, case changes, find and replace, MusicBrainz album lookup, covers from cover.jpg or folder.jpg, lyrics from LRCLIB, CSV export and import, and M3U8 playlists. To rename files from their tags, use Tools, then Rename files from tags.

Renaming a folder in place needs a recent Chromium browser. If it refuses, turn on “Rename folders by copying” in Filters and options. Renamed files get a new modified date on some systems.

Good to know

  • Undo and backup files sit next to your files, so they travel with the folder. Delete them whenever you like.
  • Supported audio: MP3 (ID3v2.3/2.4 and ID3v1), FLAC, M4A/M4B/AAC/ALAC, OGG Vorbis, Opus, WAV and AIFF. Fragmented MP4 files are not edited.
  • Everything you type and every preset stays in this browser. Nothing is sent anywhere.
